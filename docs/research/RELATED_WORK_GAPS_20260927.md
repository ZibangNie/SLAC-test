# 论文贡献边界与近期工作核对

日期：2026-09-27。此项在77题扩展实验执行期间完成，不根据其尚未完成的结果修改方法或分母。这是若干最接近方向的一手来源核对，不是穷尽检索，也没有复现这些论文的成绩。

## 已有工作覆盖的主张

| 一手来源 | 已明确研究的内容 | 对 SLAC × JEV 的要求 |
|---|---|---|
| [DPS: From Ranking to Selection](https://arxiv.org/abs/2508.09497)，2025 | 以监督学习进行动态段落选择，并显式考虑段落间依赖，针对固定top-k的遗漏/噪声问题 | “从排序改为选择”“动态数量”“考虑依赖”不能单独作为新贡献。需说明共享文档关系的具体机制、比较条件和不同之处。 |
| [BAR-RAG](https://arxiv.org/abs/2602.03689)，2026 | 用生成器反馈训练证据选择器，并配合生成器训练处理证据分布差异 | 最终答案表现必须实测；只用Evidence F1不能证明更适合生成。其boundary指生成器可回答难度边界，不能误写成与SLAC文本分块边界相同。 |
| [Late Chunking](https://arxiv.org/abs/2409.04701)，2024，现读v3 | 在长文token表示计算后、pooling之前再分块，使单块向量保留周围上下文 | “保留跨块上下文”已有强相关方案。分块策略和embedding时机必须分开，不能把更长编码上下文的收益全部归给关系。 |
| [Is Semantic Chunking Worth the Computational Cost?](https://arxiv.org/abs/2410.13070)，2024 | 检查语义分块在检索、证据检索和答案生成上的质量与成本，报告其收益并不一致 | 保留简单固定长度/段落基线，记录构建成本和实际证据长度。不能默认复杂分块一定优于规则。 |
| [Beyond Chunk-Then-Embed](https://arxiv.org/abs/2602.16974)，2026 | 区分分块方式与embedding范式，同时比较给定文档与跨库检索，报告设置依赖性 | 当前given-document结果必须保持这个名称；跨库SLAC实验另行冻结，不能直接跨设置比较。 |

这些观察只排除了过宽的创新表述，不证明本项目没有贡献，也不证明候选贡献已经成立。

## JEV 新颖性与可验证优势

[TypeSafe发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)把JEV定位为面向有限类型判断的模型，强调概率输出及结构化工作流。它适合将语义判断交给模型、将预算与组合约束交给程序的设计；这部分是产品能力，不是SLAC自己的方法贡献。厂商关于校准、速度和费用的论述不能直接作为我们在RAG上的实测结论。

现有15题开发诊断发现原始分数排序的改善信号，但也观察到两条返回值总和为0.99。我们的reported-scores契约没有归一化或声称校准；分数和为1也不能单独证明校准。需要独立参考标注才能检验决策校准，不能把“未命中Qasper人工证据”直接当作语义不支持的真负例。

## 目前可保留的可证伪候选贡献

1. **有来源定位的关系跨阶段复用。** 同一文档关系实际改变分块及证据选择，而非仅复用相同API结果。比较同后端的独立处理、普通缓存、共享决策，并加入简单邻接或固定随机关系对照。原15题S尚无额外F1收益，不能先写成已验证贡献。
2. **预算约束下的便宜判别工作流。** 比较JEV粗标签/原始分数、强cross-encoder重排和合理合批通用LLM；报告最终答案、真实证据长度、各阶段费用、延迟与失败。若仅替换后端降低价格，其价值更接近系统实证，需要多数据集和稳定的质量—成本结果支持。
3. **编辑式Boundary Refiner的独立价值。** 与同输入、含b0状态、同编码器/容量/训练预算的最终边界分类器比较。既有微型训练诊断未显示Refiner优势，旧repaired legacy标签仍不具备正式训练准入，不能用开发成绩反复训练后宣称泛化。

三项可以分别不成立。接下来的实验应允许去掉没有收益的模块，而不是让最终论文必须包含所有现有工程组件。

## 距离投稿级证据仍缺什么

- 当前77题是扩展开发验证，不是独立确认。最终独立数据、family/近重复审核、预先固定分析与跨数据集复现仍待完成。
- 需要强重排基线；现阶段dense、粗标签和通用LLM比较尚未穷尽合理基线。添加任何新模型时锁定checkpoint、输入截断规则和实际预算，不能让某一方法额外获得全文。
- 需要真实chunk→index→retrieval→pack链路。旧检索入口的pooling、512-token截断和估计token打包与现研究规则不同，必须通过独立适配器统一并审计。
- Qasper金标为native段落。chunk只覆盖段落一部分时，不能把该段全部算作已获得；若统一扩展回完整native段，应保存投影规则并按实际返回文本重计tokens。
- 静态关系构建费、embedding/index费、query判断费和生成费分别计账。离线回放复用不等于实测冷/热缓存或低延迟。文档多query摊销需真实实验。
- 原理解释不能只依赖模型自己评价。现有分歧富集盲审材料尚无人类标注，不能当作人工确认的关系/必要性金标。
