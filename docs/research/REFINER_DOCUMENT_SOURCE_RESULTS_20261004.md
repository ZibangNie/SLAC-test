# Refiner 文档来源坐标与同文本预算／导出

2026-10-04。沿用此前固定的两篇开发文档、83 个 native Unit、251 个 model atom，完成文档级来源视图与真实 exporter 的可选接入。原始 b0 的 83 个块、规则投影后的 56 个块，其新导出文本均与 projector 的预算文本逐字节一致；块和 leaf 分别拼接后都能还原完整结构化原文。53 项相关合成／回归测试通过。本轮 API、模型推理、训练、权重和金标读取均为 0。

这是工程契约验证。没有学习得到的边界、JEV 判断、答案或证据质量指标，也没有据此建立创新性或 RAG 收益。

## 接入方式与来源边界

新增 [`source_document_view.py`](../../SLAC/refiner/pipeline/assemble/source_document_view.py)，把已保存的逐单元双文本 trace 按经核验的 `raw_native_char_span` 平移到文档坐标。不可变视图分别保留规范化 `model_atoms`、来源字符区间和原文渲染区间；不会修改 Refiner 输入记录中的 `atoms` 或 b0。模型字符来源必须有序、无重叠且覆盖全部非空白原文；规范化转换、插入合并空格与真实原文保持区分。组合时拒绝未建模的非空白间隔，禁止模糊匹配或重新寻找位置来修补失败。

此处“原文”是数据集的 title、abstract、section-name、paragraph 字符串以明确双换行连接后的结构化文档文本，坐标为 Python 字符偏移，**不是 PDF 字节位置**，也不是另一个 canonical 文本的坐标。两文档共 33,109 字符，83 个单元内部共 32,947 字符；余下 81 处间隔共 162 字符，均为双换行。首尾间隔为空，没有遗漏的非空白内容。旧 `native_coverage_char_span` 的间隔归属不直接复用；新渲染统一将单元／atom 间隔归给前一个 atom，外层空白归首尾 atom。

[`export_refined_chunks.py`](../../SLAC/refiner/pipeline/assemble/export_refined_chunks.py) 的四个构建／导出入口新增显式 `source_view` 关键字参数。启用后，chunk 与 leaf 都从同一视图切片，附带 `source_char_span` 和坐标系统；外层输出还绑定完整来源文档 SHA256。来源标记为 `refiner_source_view`，候选边界元数据保持显式。文档 ID 和规范化 atoms 的绑定检查在 `strict_validate=False` 时仍执行。

未传入视图的默认行为保持原样：两篇完整旧恒等导出 JSON 值精确复现，四组有／无 leaf、catalog 的合成完整输出快照不变。本轮没有把可选来源视图接入默认模型推理脚本。

## 固定样本结果

三份旧输入以 SHA256 固定：有界原文／映射、原始恒等导出、上一轮保存的双文本 trace。本轮没有重跑 atomizer，也没有新增抽样。全部 2/2 文档、83/83 单元、251/251 atoms 通过文档组合；失败数为 0。

四组导出均无硬上限违规。来源与旧模式得到完全相同的投影边界；各自移除 27 个边界、未增加边界，剩余软下限不满足项为 0。规则投影使用 b0，没有模型 gap scores；其边界变化不能归因于 Refiner 学习效果。

包含完整文档间隔的来源导出，相对旧导出有 81/83 个原始块多 1 token、2 个相同；投影后有 54/56 个块多 1 token、2 个相同。此前逐单元检查没有加入单元之间的间隔，因此不能沿用旧 token 差分。这里只报告渲染表示的实际差值，不把差值全部归因于某一种规范化操作。本样本的变化尚未触发不同边界，不等于任何文本都不会触发。

## 验证与后续约束

21 项来源视图测试覆盖重复文本、局部坐标平移、空白单元、不可变性、来源缺口、错序和非法字符来源；18 项 exporter 测试覆盖默认快照、四个入口绑定、候选选择与真实 projector 联通；14 项已有 seed 映射回归测试保持通过。合计 **53 passed in 0.21s**。一个错序测试最初期待较晚的重叠错误，实际更早因非空白缺口而被正确拒绝；仅修正测试期望，生产实现未修改。

实际 projector 的合成反例使用 `a.     b.`：规范化文本可在上限 8 内合并，保留五个空格的原文必须拆分；新 exporter 输出逐字节等于投影结果且满足同一上限。这是必要性的反例，不是自然数据效果。

独立复核分别验证输入坐标和已保存输出，不重跑组合／投影／导出算法；原文分区、字符来源、完整重建、每块预算及来源绑定的核验信息保存在[机器结果](results/refiner_document_source_20261004.json)。公开材料只使用文档序号，不包含原文、问题或原始文档 ID。

下一步继续零 API，检查新 chunk 与旧 native Unit 的完整／部分覆盖关系及 JEV 文本身份契约。新来源块即使来自同一单元，也不能直接继承旧文本的判断、分数或 API 缓存命中；跨单元合并与部分段落覆盖也不能被当作整段证据标签。未来质量比较仍需分别保留原始 b0、规则投影 b0 和相同规则下的学习边界。
