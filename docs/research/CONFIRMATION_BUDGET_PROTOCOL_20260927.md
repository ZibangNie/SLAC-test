# Offline confirmation support and answer budget plan

2026-09-27. This stage computes a plan from a complete, already audited 248-document candidate run. It does not execute requests, read credentials or references, load model weights, calculate quality, or admit a paid run. It inherits the completed candidate sample audit; it does not repeat retrieval or expand content inspection. The historical night ledger, its $5 cap and 09:00 deadline remain closed and are not this stage's authorization or limits.

For every saved query, retain all candidate support tasks in their original native order. Reuse the frozen `freeze_batches`, `make_payload` and `reservation` helpers with the explicit `qwen36plus-json` profile. A common batch has at most eight items and must fit 24,000 bytes in canonical UTF-8 for **both** backends. Split a batch when either backend requires it; reject an indivisible overlength task without truncation. Never mix questions into a batch. One JEV judgment feeds both `I_jev_k3` and `p_yes_only_k3`; it is not purchased twice. General judgments feed `I_general_k3`. No static relation calls are planned.

Let Q be the complete number of questions, C the sum of their candidate-unit counts and B the number of common batches. There are B JEV and B Qwen requests, C judgments per backend, and 2B support requests in total. Save complete payloads, task identities, byte lengths, hashes and individual reservations privately. Public output contains counts and sums only. JEV input allowance is `(canonical_payload_bytes + 2048) × batch_items`; general input allowance is `canonical_payload_bytes + 2048`. Both reserve 1,024 output tokens. Apply each frozen model's per-million input/output prices, a 1.5 multiplier and a $0.005 request floor. These are exact formula results for the frozen support payloads, not forecasts of exact provider charges.

For the five fixed arms (`dense_k3`, `reranker_k3`, `I_jev_k3`, `I_general_k3`, `p_yes_only_k3`), reserve a conservative **conditional** answer bound of 5Q requests, with no cache or duplicate-payload discount. At 24,000 payload bytes plus 2,048 allowance, 512 output tokens, Qwen's $0.325/$1.95 per million prices, 1.5 multiplier and $0.001 floor, the per-request upper reservation is $0.014196. Thus generation's conditional upper reservation is `5 × Q × 0.014196`. This does not construct the actual answer payloads, prove they fit the byte cap, or determine their exact unique count. A 1,024 BGE evidence-token budget alone does not prove a full generator payload fits. Later planning must build and check every actual payload before admission.

Bind the dated public provider snapshot, its model/provider identities, explicit profile, source hashes, base prices and reservation contract. HTTP metadata availability is not authenticated inference availability, an account-credit check or a guarantee of the actual returned revision. Do not silently replace providers, raise price assumptions, use cache discounts or introduce retries. A changed contract requires a new plan.

The loader accepts only the completed candidate run and its completed sample-audit receipt. It verifies their complete file commitments and necessary plan metadata, reads the saved model-visible prepared container, and validates complete query-to-candidate support coverage. It does not open evaluator references or inherited source text/tokenizer/model files again; those commitments are labelled inherited. All private plans and source paths stay in a new ignored directory; outputs cannot overwrite or nest inside their inputs. The command has no execution mode. A new paid-stage cap and absolute deadline remain explicitly unset.
