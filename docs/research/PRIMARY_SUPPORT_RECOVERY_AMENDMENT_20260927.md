# 主 support 的一次有界恢复修订

状态：**执行前协议；本文自身不启动请求，真实执行仍需冻结 plan、独立 review 和随后的 Root release**。本文件与数字核对只使用已冻结的本地配置、请求和账本；没有调用 API、读取密钥、创建恢复执行计划或计算未完整 support 的质量。Root 已决定在用户既有整晚自主推进和 API 授权范围内采用下述一次操作修订；这不表示用户单独确认过这次重发，也不使原协议自动允许重试。新执行器、合成测试、完整来源绑定和本协议仍须冻结并通过独立审阅，Root 才能放行。

## 1. 为什么需要修订

原 77 题、24 family 的 support 计划含 308 个逻辑请求。已验证的旧执行留下 164 次成功、终末第 165 次传输超时且费用未知、143 次未尝试。原协议要求遇错停止、不自动重试；旧执行确实遵守了它。未完整覆盖的 support 不形成主质量结果。

[夜间协议](OVERNIGHT_RESEARCH_20260927.md)规定的禁止自动重试是本次研究自行冻结的运行策略，不是“每次重试必须重新征得用户许可”的单独用户指令。[超时恢复说明](OPENROUTER_TIMEOUT_RECOVERY_20260927.md)也明确，未来若重发必须另立公开协议、保留旧未知记录和全部预留。没有可验证的 generation ID，不能把再次发送说成读取旧结果、幂等恢复或免费请求。

本修订只改变终末未知逻辑项的一次恢复处理和后续生成预留的规划规则。数据、候选、任务、payload、顺序、provider、模型身份、选择算法和统计比较不变；不依据 partial 质量决定是否恢复。

## 2. 固定恢复顺序与不可变来源

1. 对旧成功 164 项逐项验证原 request、response、ledger、计划和审计的哈希及解析合同，直接继承。不得重新调用、重新选择响应或把它们记作新收费。
2. 原第 165 个逻辑项（零基 `schedule_index=164`）允许**至多一次**明确关联的重复尝试。新物理尝试必须保存旧 run、旧 segment、旧 attempt、原逻辑序号、原 request SHA 和旧未知状态的指针。已核对原请求 SHA 为 `e4f9761f3a47204973ffe51ac8ebdff71808b0e66b01211e66fda46e54754c80`；执行冻结仍必须从旧审计绑定实际读取并逐字节核对，不能只依赖文档中的手录值。
3. 重复尝试成功并通过全部模型、usage、结构校验后，按原顺序执行逻辑 166–308 的 143 个未尝试项。不得先跳过未知项去挑可完成请求。
4. 任何新异常、拒绝、超时、未完成终止、费用或模型异常立即停止。旧失败仍在，新失败另记；本修订不允许第二次恢复、自动重试或换目录重置额度。
5. 全部完成后应有 **308 个逻辑请求、309 个物理尝试、308 次有效成功和 1 次历史未知**。不能删掉未知，不能称为 308 次物理调用。若新尝试再次失败，只保存已验证进度和账目，不输出完整主结果。

新代码必须保持旧 source、plan、failed run、execution registration 和 interruption audit 不变。使用新的派生 schema 和独立的单次执行注册；注册与父链绑定，防止从另一个输出目录再次启动。每项先持久化预留和 in-flight 身份，再发出请求；崩溃后不得猜测“没有收费”或自动继续。

冻结锚点：原 experiment config SHA `382cc127c5957d76fbb4fc0ec30cd469b66ef542a7f76b1d01131b9f839c5e55`；原 plan manifest SHA `0f4182624ae9d68966ac8c3c0838bcfbe34d635606be67307b1d19f73270fc3f`；中断 audit SHA `98fe51d25b8c9593b6d7f2c8aaa6df08ee9d7997802f06873162e01c0dfeb8e3`。执行器须核对实际文件及完整传递依赖，而不只相信文档中的锚点。

## 3. 不变的模型与运行边界

- JEV 请求仍为 `typesafe/jev-1.13`、TypeSafe、原 alpha decisions 路由；实际响应身份必须与既有成功记录的 `typesafe/jev-1.13-20260917` 一致。
- general 请求仍为 `qwen/qwen3.6-plus`、Alibaba、原 chat completions 路由；实际响应身份必须与既有记录的 `qwen/qwen3.6-plus` 一致。较宽旧 allowlist 中存在另一别名，不足以允许此次实际身份漂移。
- 原任务 payload、`slac-local-decision-v1`、完整 candidate 和判断项、输出 allowance、价格上界、无 fallback 均不变。JEV reported-score 合同仍沿用旧冻结处理，不将原始分数解释为校准概率。
- 单 segment 继续最多 160 calls、1,600 判断项、8,000,000 input allowance、$2 预留。新 144 calls 按原交错次序确定为 124 + 20 两段，不能因新目录给予额外整夜额度。
- support 总上限仍为 $4、512 次尝试、2,600 判断项、40,000,000 input allowance；整夜总预留仍为 $5。这里“判断项”不是 Qasper 题目，主问题分母仍为 77。
- 每请求前检查原 UTC 截止 `2026-09-27T01:00:00+00:00`（本地 09:00）和原 5,400 秒单运行时限；保留原 65 秒余量门禁。不得把恢复解释为延长夜间窗口。报告旧、新执行时间及中断间隔，单独给新执行时长，不隐去旧等待成本。

## 5. `$1` 生成预留的准确含义与修订

旧 `run_qasper_extended_development.CAPS` 的 `generation_minimum_reserve_usd="1"` 是冻结配置中的规划字段。源码没有将它记作 ledger 消费项，也没有要求答案生成必须花到 $1；support≤$4 与 night≤$5 最初提供至少 $1 的可用空间。原完整 support 计划的估算预留事实上是 $2.7656216375，原计划还计算了相应的剩余额度。

后来完成的两轮答案已消耗 $1.3633746750 **预留额度**。既不能退回它们，也不能用“此前已花够 $1”宣称现在仍有新的一美元可用。如果此次恢复后仍要求额外保留未消费的 $1，合计会达到 $5.1353945925，超上限 $0.1353945925。

本修订将这个粗略的未来 $1 headroom 改成：**support 全部完成后，对原固定六组、全 77 题的答案 payload 完整构造，按精确缓存继承和完整去重计算新增生成预留 G；仅当 G≤$0.8646054075，且整夜全父链预留 + G≤$5 时，才可冻结并另行放行答案阶段。** 这是公开的规划修订，不是旧字段一直如此执行的声称。恢复 support 的放行不等于答案阶段已被放行。

旧 `run_qasper_answer_evaluation.plan` 只继承其 support run 的账目，早于后来的 367 + 7 次生成；它还不理解失败前缀加关联重复尝试的恢复父链。**不能直接原样启动它**。未来答案适配器必须继承整夜父链和旧 unknown，保持同一 $5 预算，并理解恢复结果的完整审计来源。

本次离线核对了两轮完整且已审计的答案来源、全部 374 个已完成唯一请求的原 payload 和 request/response 哈希，并以原冻结 dense pack 重建主 dense/empty payload：

|---|---:|---:|
| dense_k3 | 77 | 77 |

这 154 个历史请求对应的 $0.5196642750 预留早已包括在整夜父链，继承时不再次收费，也不从父链扣除。其余四组共 308 个逻辑预测，可能相互去重，也可能命中剩余历史缓存；**确切 pack、唯一新请求数和 G 尚不能由未完整 support 得知**。当前不能承诺剩余 $0.8646054075 足够。

缓存身份必须是 endpoint、prompt version 和完整 canonical payload；除哈希外还需完整 payload 相等，继承来源必须是合法完成响应，实际 generator 必须仍为 `qwen/qwen3.6-plus` / Alibaba。不得仅按选集、pack hash、方法名或回答相似度复用，不能用 partial support 来估计有利命中。全部重复逻辑预测仍保留在 462 分母中，共享响应只是一种实验去重，不是测得的生产缓存收益。

精确 G 必须先对所有六组构造并去重，再统一做预算准入，不能边发边看余额。若 G 超额，答案阶段整体不发新请求；保留完整 support 结果和预算不足记录，不能删题、删方法、改长度/模型/价格规则，或只发布有缓存/表现好的组。若获准执行后再失败，则保留全账并停止，主答案比较仍不完整。
