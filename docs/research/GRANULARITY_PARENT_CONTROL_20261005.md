# 评分粒度与输出范围：已有方法对照及三臂修订

2026-10-05。**细单元评分后返回或合并较大上下文已有直接先例，不能作为 SLAC × JEV 的创新主张。** 本轮只给已有两题的粒度诊断补一个必要对照，没有获得新模型分数、答案或效果结果。原[两臂协议](CANDIDATE_GRANULARITY_PROTOCOL_20261005.md)、117 个冻结输入配对和失败运行保留不变。本修订在新评分输出前记录，但问题、参考和历史结果已曝光，仍是开发性诊断。

## 针对机制的四篇相关工作

| 工作 | 已覆盖的机制 | 对当前假设的限制 |
|---|---|---|
| [Dense X Retrieval](https://arxiv.org/html/2312.06648v2)，§4.3–4.4 | 以细粒度句子／命题与 query 的相似度最大值评分原 passage，返回去重父 passage；还比较固定检索词数下的 QA。 | “子块评分、父段输出”是已有基线。命题可能改写及消解指代，其词数截取也不同于这里的原文区间和整块预算。 |
| [Late Chunking](https://arxiv.org/html/2409.04701v3)，§3 | 先编码长上下文，再按块池化，给小块保留上下文表征。 | 保留上下文的细粒度检索不是空白；它属于 embedding 路线，并非 query 条件下的 JEV 判断。 |
| [HiChunk](https://aclanthology.org/2026.acl-long.1372.pdf)，§4–5 | 按 query 排序细块，依据层级覆盖比例及剩余 token 预算向父块合并。 | 层级细检索与预算约束合并已有研究。这里仅拼接相邻已选原文区间，不等同于其父块扩展算法。 |
| [SmartChunk Retrieval](https://arxiv.org/html/2602.22225v1)，§4 | 根据 query 规划块粒度范围，结合层级压缩 embedding 检索。 | “按问题调整粒度”本身不足以区分方法；它也不等于本项目的无损来源渲染。 |

这是聚焦机制的四篇核查，不是穷尽性综述，也未证明任何更窄方案具有新颖性。原文来源验证和完整渲染预算是控制变量及工程要求，不能独立充当质量收益或论文贡献。

## 新增 B 臂，保留原 A／C 臂

| 臂 | 排序分数 | 可选及输出内容 |
|---|---|---|
| A：原完整单元 | 新 BGE 对完整 source Unit 直接评分 | 完整 source Unit |
| B：parent-max 对照 | 同一父单元内全部 source atom 的新 BGE 分数最大值 | 完整 source Unit |
| C：原 atom 臂 | 新 BGE 对各 source atom 直接评分 | source atom |

B 是 **Dense X 风格的已知对照**，不是该论文复现：评分器、细块构造、输出预算和数据不同。A→B 保持候选输出单元相同，帮助检查评分粒度；B→C 复用同批 child 分数，帮助检查选择和输出范围。max 可能偏向子块较多的父单元，不是校准后的父单元相关概率，更不是父单元 JEV `yes`。禁止继承旧段落分数或旧 JEV 标签。

三臂的允许来源字符域相同，继续使用原排序同分规则、单次贪心扫描、仅合并相邻已选原文区间、最多三个输出区间和完整 evidence block 的 1,024 BGE proxy-token 上限。跳过的候选不回访，不截断、不跨空隙补文本。预算不含系统／query message／供应商 framing／输出，不能解释为账单 token。

分数分布、max 与子块数量的关系、不同粒度的上下文长度、候选数及贪心前缀可行性仍混杂，不能把 A/B/C 差异都解释成模型理解能力。它们也不包含 learned Refiner，因而不能证明 Refiner 的贡献。

## 本次完成与未完成的范围

[纯函数实现](granularity_lift_control.py)要求每个父单元有唯一完整候选，子块严格连续覆盖其原文区间；拒绝错属、缺口、重叠和不一致 Dense rank。相同模型输入可以共享 task ID，但每个提升后的父候选使用独立内部 ID，防止不同父项的最大值互相覆盖。结果保存全部并列最大贡献者，不修改真实模型分数，也不产生语义标签。

八项合成测试通过，只验证上述执行契约。另以[有界准备脚本](prepare_granularity_parent_control.py)检查原冻结两题的 30 个完整单元、97 个 atom 与 117 个模型配对：B 不引入额外评分文本或模型调用。[匿名准备记录](results/granularity_parent_control_20261005.json)保存实际计数和输入绑定；原文及身份留在私有准备目录。这里没有给自然样本编造替代分数。

目前没有可用的 fresh scores。上一轮唯一模型尝试失败且无成功 manifest；本轮 GPU 检查仍为 1,453 MiB 空闲／63% 利用率，不满足原准入条件。本轮没有重试、加载权重、分词、API 或训练。原评分器和四包分析入口仍是两臂版本，**本修订没有把三臂执行接入它们**；未来需要独立执行记录和适配入口，不能直接重跑失败的 run-01 或宣称六包已可执行。

## 执行后的判据

若以后完成相同 117 对的合法新评分，先冻结全部六个选包和 B 的 max-contributor 记录，再读取已保存的四份参考区间；报告全部十二条 annotation×方法结果。保留字符交集、precision/recall、完整覆盖、来源字符数和整块 tokens，以及候选域覆盖上限。禁止选择有利 annotation、合成参考或套用原段落 Evidence F1；本探测不生成答案。

若 C 相对 B 没有观察到参考覆盖与资源上的优势，或差别在共同包装后消失，则不以该机制作为扩大 JEV 调用的依据。即使出现改善，也只能支持一次后续有上限的跨模型探测；它不能单独证明 SLAC 特有机制、JEV 效果、回答质量或论文新颖性。未完成的模型诊断继续保留，不因等待 GPU 而扩大数据或付费计划。
