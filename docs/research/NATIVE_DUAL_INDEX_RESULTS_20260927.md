# Qasper 规则 chunk 与双索引对照：2026-09-27

完整运行与独立 CPU 审计通过 **77 题、24 个 family、6 组、462 条记录**。核心同分区比较为 **`dual_owner − leaf_owner`**：指定文档来源限定 Evidence F1 的 question-weighted 均值从 **0.143845 降至 0.139207**（Δ −0.004638），32 篇跨库从 **0.104359 降至 0.093143**（Δ −0.011216）；两种任务的双加权 F1 区间均跨零。指定文档 family-balanced F1 点差为近零的 **+0.000496**，跨库为 **−0.017203**，保留不同加权方向。

新增 chunk 通道的候选来源限定 recall 点估计分别增加 **0.014502 / 0.012987**，按问题加权的最终 F1 没有得到相应的正向点估计；跨库 evidence 包平均增加 **30.416 tokens**。本轮验证了可运行、可回放的规则 chunk / owner 聚合桥接，尚未证明增加 chunk 检索能改善最终证据质量。这些 chunk 来自固定规则，**不是 JEV 关系分块或 Boundary Refiner 输出**，不能作为完整 SLAC、JEV 或答案质量的成败证据。

## 数据、分区和比较边界

`given_document` 已知来源论文；`corpus_32` 仅用原问题字符串搜索已有 32 篇 validation 论文。Qasper 原问题是在特定论文标题和摘要的上下文中提出的，所以跨库组是额外构造的 query-only 压力诊断，不能称作标准全库 Qasper 评测。[Dasigi et al., NAACL 2021](https://aclanthology.org/2021.naacl-main.365/)

全部 24 个非 pilot family 的 77 题始终保留，原 8 个 pilot family 的论文仍可作干扰文档；没有筛掉不可回答、空参考或图表证据题。数据已暴露于开发实验，不构成独立确认。参考只进入评分，不用于分区、编码、排名或打包。

[预先固定协议](NATIVE_CHUNK_BRIDGE_PROTOCOL_20260927.md)保留原 **1,850 个 native leaf** 与缓存顺序。在同 section 内贪心合并相邻完整单元，通常上限 **512 个 BGE tokens**；**10 个**本身超限的单元完整保留为 oversize singleton。得到 **671 个规则 chunk**，每块单元数最小/P50/P95/最大为 **1 / 2 / 6 / 19**，不按 gold 或检索结果改变分区。

chunk 编码前冻结全部输入 IDs，共 **187,607 tokens**，长度最小/P50/P95/最大为 **11 / 276 / 505 / 787**，全部低于 8,192，无截断。模型固定 BGE-M3 revision `5617a9f61b028005a4858fdac845db406aefb181`，FP16 backbone、CLS、FP32 L2，microbatch 4；输入严格为完整 `ChunkRecord.text`，没有另加 path、anchor、指令或 query。leaf/query 复用经 hash、索引和表示验证的缓存，没有再次编码。

| 方法 | 固定行为 | 比较角色 |
|---|---|---|
| `leaf_direct` | dense 前 8 leaf，加同文档相邻单元至多 16 候选，按 leaf 分数选包 | 直接 leaf 背景基线 |
| `leaf_owner` | 前 8 leaf 映射 owner，按生产 RRF 聚合，保留至多 8 owner，再投影回完整 leaf | 核心单通道对照 |
| `dual_owner` | 相同 leaf hits、相同分区与聚合，另加入前 8 个 dense chunk hits | 核心新增 chunk 通道 |

两个 owner 方法共用生产 `aggregate_hits_to_chunk_candidates` 与 `fuse_candidate_scores_rrf`、RRF `k=60`、generic intent 和 owner tie policy。投影按 owner 融合排名，owner 内按 leaf 分数与冻结行号排序，最多 16 个唯一 `(doc_id, unit_id)` 候选。**核心增量由 `dual_owner − leaf_owner` 衡量**；与 `leaf_direct` 比较同时改变 owner 聚合和候选顺序，不能把差异全部归因于第二索引。

六组均按自己的候选顺序、`(doc_id, native_text)` 去重，选择最多 3 个完整单元，最终按全局原文顺序渲染，整个包不超过 1,024 个实际 BGE evidence tokens。超长单元跳过、不截断；实际每组每题均选 3 个，共 231 个最终单元，0 空包。预算上限相同不意味着实际包长度相同。

## 核心增量：dual_owner − leaf_owner

## 背景比较与机制解释限制

指定文档 `leaf_owner` / `dual_owner` 相对 `leaf_direct` 的来源限定 F1 点差为 **−0.058608 / −0.063246**，双加权描述区间都在零以下。跨库相对 direct 的点差为 **+0.022232 / +0.011016**，双加权区间都跨零。下方附表保留全部负向背景比较，不用跨库正点估计掩盖指定文档下降。

owner 路径候选 recall 可以高于直接 leaf，而最终 top-3 F1 仍较低。这提示另行检查 owner 投影与排序对最终选择的影响；本轮没有隔离这些因素，不能作因果归因，也不能事后挑选方法宣称收益。

生产 RRF 对**每个 leaf hit**给 owner 一票，同一个大 owner 内多个 leaf 会累加。这些是多个检索命中，不是独立语义关系证据。核心两方法保持同一分区与计票规则，dual 另加 chunk 通道。下表“首 owner 多 leaf 命中”是保存 trace 的描述性计数，不能量化重复计票的独立因果贡献；“跨文档重复原文组”是另一文本诊断，与 RRF 多票不同。

## 计算成本、执行和审计

新增一次 **671 个 chunk 的 GPU 编码**，用时 **7.781000 秒**；设备 **NVIDIA GeForce RTX 5070 Laptop GPU**，CUDA runtime **13.0**，PyTorch **2.9.1+cu130**，Transformers **4.57.3**。PyTorch 峰值 allocated / reserved 为 **1206025728 / 1247805440 bytes**（约 1.123 / 1.162 GiB），不等于整卡显存占用。新增 API 调用为 **0**，没有训练或答案生成。
