# Fixed analysis for the prospective Qasper cohort, 27 September 2026

This protocol adopts the five-arm method and statistical choices in the [design review](CONFIRMATION_DESIGN_REVIEW_20260927.md), before any new-cohort prediction or quality result. It is an analysis commitment, not admission of a dataset or paid run. The old 77-question development results motivated the design and remain development evidence. No new QA is opened at this stage.

## Fixed methods and population

Use `dense_k3`, `reranker_k3`, `I_jev_k3`, `I_general_k3` and the single score method `p_yes_only_k3`. Each uses the same given-document candidate pool, native-text deduplication, at most three units and at most 1,024 actual BGE-tokenized evidence tokens. Use the inherited whole-pack skip-overflow procedure and native rendering order. Score ordering uses the reported yes score directly; do not fit thresholds or renormalize scores. These are comparisons of complete selection procedures, with the same evidence cap but potentially different actual lengths. They do not establish a length-independent effect or an end-to-end SLAC advantage.

Apply the [metadata source policy](CONFIRMATION_METADATA_PROTOCOL_20260927.md) to the entire validation denominator and preserve every proposed component. The proposal is not a certified independent holdout. Before later admission, explicitly retain the historical whole-member machine-decoding record, unknown external/model-training exposure and component-independence assumptions. Use every question in an admitted component, including unanswerable, figure/table and evidence-unreachable cases. Do not select documents or questions by references, method outcomes or a favorable sample size. The restricted question inventory is not available yet; a later export must bind it before predictions. Statistical `family_id` must identify that frozen operational component, with the original source family retained in a separate private mapping.

## Single inferential analysis

The outcome is official max-over-reference Answer F1. Compute paired mean differences within each complete component, then give each component equal weight. The primary comparison is score minus BGE; the two key secondary comparisons are score minus JEV ordinal and score minus Qwen ordinal. For these three comparisons jointly, use two-sided t intervals with Bonferroni familywise alpha 0.05, critical quantile `1 - 0.05/(2*3)` and `F-1` degrees of freedom. Publish all three intervals regardless of direction. A lower endpoint strictly greater than zero supports only its specified claim; a zero-containing interval is inconclusive. Dense, token and question-weighted comparisons cannot rescue the primary claim. A zero sample SD makes this proposed t inference unavailable; a positive collapsed interval cannot count as confirmation.

Report all five arm means for Answer F1 and actual evidence tokens under both question and family weights. For each of the four score-minus-comparator contrasts, both metrics and both weights, publish all 16 descriptive paired family-bootstrap intervals: 10,000 shared PCG64 draws, seed 20260927, linear 2.5% and 97.5% quantiles. Recompute the question-weighted denominator when whole components are sampled. These descriptive intervals are not simultaneous inferential evidence. Include wins/ties/losses. Record selected-unit, empty-pack, abstention, response-coverage and request-resource summaries in the later execution report; the analysis function's six-field score contract does not substitute for those operational records.

The designated conditional precision target is 193 comparable independent components, based on the development SD times 1.5 and adjusted half-width 0.05. Record whether the proposed/admitted count reaches that target; do not truncate a larger cohort or top up a smaller one after seeing outcomes. This is planning arithmetic, not power or guaranteed coverage. The t and cluster-bootstrap procedures assume adequate component independence and a suitable sampling population; neither establishes those facts. One stored response per payload does not estimate generator variation.

## Implementation and failure contract

`analyze_qasper_confirmation.py` consumes a complete question manifest and exactly one score row per question and arm. Reject duplicate/missing/extra rows, conflicting component identity, nonfinite or out-of-range F1, noninteger or over-budget evidence tokens and fewer than two components. Do not impute failed requests as wrong answers or model abstentions. The pure function performs no network or dataset reads and is tested only with synthetic examples before sealing.

The public machine protocol binds this document, the design review, implementation and synthetic tests by exact byte hash. It freezes the analysis choices before new outcomes but leaves question counts, current provider contract, candidate manifests, whole-cohort support/generation budget and absolute execution deadline explicitly unresolved. A separately sealed export and execution plan must satisfy those checks; the expired overnight run and its ledger remain closed. This protocol introduces no extra user-permission or universal manual-review requirement.

Exact model/prompt/provider/tokenizer bindings and complete task coverage must be fixed before later model execution. Returned-model changes, malformed output, timeout, missing judgment or source/hash drift halt that run without automatic retries or fallback. No primary quality result is issued from a successful subset. Any recovery requires an explicit dated amendment preserving the original failed/unknown attempts and coverage. No paid execution is admitted by this analysis protocol.
