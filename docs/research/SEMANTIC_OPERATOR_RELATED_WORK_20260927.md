# Semantic-operator optimization: additional novelty check

Checked 27 September 2026 against primary sources. This is a literature comparison, not a reproduction or performance comparison. It supplements the earlier [dependency-selection review](RECENT_RELATED_WORK_20260927.md) and [decision-diagram review](RELATION_DEMAND_DESIGN_REVIEW_20260927.md). A new JEV interface, inexpensive judgments or fewer requested labels alone would not establish a new optimization principle.

| Work and inspected version | What the primary source establishes | Consequence for the SLAC study |
|---|---|---|
| [LOTUS / Semantic Operators, arXiv v3](https://arxiv.org/abs/2407.11418v3), revised 1 March 2025; abstract and HTML overview inspected | Declarative semantic filtering, joining, grouping and ranking have multiple physical implementations. The work defines reference behavior through a gold algorithm and optimizes execution with accuracy guarantees relative to that reference. | Typed semantic operators and cost-aware execution are existing research directions. Our exact finite pack-function equality differs from an approximate operator-quality contract, but this difference alone is not evidence of novelty or superiority. |
| [Palimpzest, CIDR 2025](https://vldb.org/cidrdb/papers/2025/p12-liu.pdf), official proceedings abstract inspected | A declarative system searches models, prompting choices and related execution alternatives to trade off runtime, monetary cost and output quality. | Choosing a cheaper judge or an execution plan is not by itself a new architecture. A systems claim needs complete workload costs and an explicit quality constraint, beyond stored-response fee totals. |
| [Larch, arXiv v1](https://arxiv.org/html/2606.07923v1), 6 June 2026; abstract, introduction, background and problem formulation inspected | The preprint studies adaptive ordering of multiple semantic predicates. It uses learned selectivity or an actor-critic policy and Boolean short-circuit evaluation to reduce token cost; its formulation resolves an AND/OR tree after enough predicate results are known. | Adaptive semantic-judgment scheduling and avoiding unnecessary LLM calls are already explicit goals. Our current native-order compiler does not optimize order or learn selectivity, and this batch shows no variable empty-cache depth. These differences limit, rather than establish, a competing systems contribution. |
| [ScaleDoc, arXiv v2](https://arxiv.org/abs/2509.12610v2), revised 3 March 2026; abstract and version metadata inspected | Offline semantic representations support query-time lightweight proxies; an adaptive cascade forwards ambiguous cases to an LLM under accuracy targets. The arXiv record links a related ACM DOI. | Offline reusable representations and selective expensive inference have precedent. Our Boolean output-dependence check is not a calibrated proxy, an accuracy-targeted cascade or a validated replacement for full labels. |

The Larch citation is to a June 2026 preprint. Its HTML contains unfilled publication-template fields; those are not evidence of an accepted venue or a 2018 publication. LOTUS's current official abstract differs from older search snippets, so this note uses v3 rather than mixing version-specific claims. No speedup figures from these papers are imported into our result tables.

Our interpretation is that a useful future distinction must be more specific than semantic caching, cheaper judgments, adaptive evaluation or dependency-aware retrieval. A candidate hypothesis is scalable elimination of judgments that provably cannot change an exact budgeted evidence pack, with the relevant control outputs preserved too. The present implementation is only a finite truth-table reference: it enumerates all assignments, is exponential, uses at most seven variables here, and does not establish production warm-cache inference or an optimization advantage over these systems. A paper pursuing that direction would need a scalable mechanism, suitable equal-output baselines, preprocessing and execution measurements, and independent workloads. It would still need to separate predicate-oracle stability from provider stochasticity and changing batch context.

The current result remains a controlled development diagnosis. This comparison neither authorizes more API calls or training nor changes any frozen experiment. It supplies a more demanding comparison set for a future method, without declaring the publication gap solved.
