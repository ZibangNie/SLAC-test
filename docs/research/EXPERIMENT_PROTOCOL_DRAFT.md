# SLAC + JEV 最小可证伪实验协议

**状态：DRAFT，2026-09-26；本文件所列科研实验均未执行。**

本草案依据迁移包研究计划和当日接手审计制定，用于基础正确性修复之后的下一阶段。编写时仅阅读研究说明与报告；没有调用 API、读取密钥或读取 test 题目/答案/证据。本轮工程修复、标签回放或小样本优化诊断均不构成下述科研结果。历史文件中的旧授权状态不是本轮用户授权的替代品；本文不额外要求重复授权，实际实验仍须满足数据有效性和可复现性条件。

## 1. 只保留一个架构主问题

**在相同原文、候选信息和最终证据 token 预算下，同一组可追溯文档关系同时参与分块与证据选择，能否比各阶段独立处理或仅缓存调用更好地保留已标注证据，并改善回答？**

近期不加入新树模型、RL、Critic、多 agent 工作流或全量蒸馏。JEV 是可替换判别后端；Boundary Refiner 是待检验的候选/边界模型。下列命题必须分别报告：

| 命题 | 可证伪对照 | 结论边界 |
| --- | --- | --- |
| H1：关系跨阶段参与决策有用 | 同后端、同候选，shared 对 cache-only | 只降低重复请求数量不能证明 H1 |
| H2：JEV 后端有优势 | 同执行方式，JEV 对合理配置的通用 LLM | 新发布、低单价或单次成功均不足以支持 H2 |
| H3：编辑机制有价值 | 同数据/编码器/输入/训练预算，Refiner 对普通最终边界分类器 | 仅恢复合成噪声或超过旧 bug 版本不能支持 H3 |

当前第一主指标只称为**预算内已标注证据保留率**。Qasper 人工证据不是唯一必要充分证据集合，也不是人工边界或条件/例外关系金标。没有额外独立审核时，不把它改称“完整语义依赖恢复率”或证明跨领域充分性。

## 2. JEV 的明确职责与版本

迁移包的真实历史调用记录为：

| 字段 | 已知历史值，尚未在本阶段刷新 |
| --- | --- |
| Provider/接口 | OpenRouter，`POST /api/alpha/decisions` |
| 请求模型 ID | `typesafe/jev-1.13` |
| 2026-09-24 返回模型 ID | `typesafe/jev-1.13-20260917` |
| 历史探针 | 18 次请求、36 个问题；仅证明当时能执行接口 |

请求 ID 与响应 ID必须分别入账。不能默认 dated 响应 ID 也是可接受的请求 ID，不能用 TypeSafe 原生接口的名称/限制替代 OpenRouter；不能把历史价格、32K 展示上限、缓存或延迟当成当前实测。正式执行前固定模型路由与 endpoint schema，记录实际返回版本；版本漂移则隔离新 run，不混入同一主比较。

最小职责只有两类，任务对象、两端和可见上下文都须写进模型可见内容，不能只放在 question ID：

1. **文档静态关系判别**：候选相邻单元是否需要连续阅读、显式引用是否指向可见定义/条件片段；输出有限标签、`unknown` 和原始分布。此结果不含 query，可在文本、上下文、任务定义及版本均相同时复用。
2. **查询相关支持判别**：当前候选是否支持给定 query，补充片段是否覆盖当前候选缺口。缓存键必须包含 query 与可见证据，不跨问题复用结果。

初期关系候选仅来自相邻单元、显式标题作用范围和明确文本引用。每个端点绑定原文 span；不枚举所有 atom 对。语义判断是软分数；覆盖、顺序、合法 ID、实际 token 上限是程序硬约束。各输出分布不相乘成声称经过校准的联合概率。

通用 LLM 后端的确切 ID、revision、结构化输出方式和生成器确切 ID 尚未选定，是实验锁定配置中的必填项；不能写一个含糊的“GPT baseline”就启动归因实验。两个后端允许合理合批、并发和缓存，并保留同并发配置的资源诊断。JEV 不负责最终自由文本回答，也不作为唯一评委。

导出应保留所有原始回答及其各自证据集合；不得把不同标注者的证据简单取并集并称唯一充分集合。图表 `FLOAT SELECTED`、无证据、无法定位、多处同文与部分定位分别标记。无法支持的模态形成公开排除计数；不悄悄只留可回答且容易对齐的题。

## 4. 分两步执行，避免因素混在一起

### 步骤 A：无新 API 的评价适配与上限

先输出稳定原文 span/atom/paragraph 映射，验证原始人工 evidence 回映一致，保留失败原因。冻结以下合理基线：固定预算、段落递归合并、部署确实可见的原生结构切分。所有方案均使用本轮修正后的公共 projector，不拿旧错误实现作为论文主基线。

在同一候选池与同一最终预算下，做**使用公开 gold 的证据选择上限**：其作用是判断候选池是否已经包含可被选中的标注证据，单列为非部署 oracle。没有人工参与时不能叫“人审最佳”。再检查允许合法重构后的 oracle；若仅后者有空间，先改候选生成，不能归咎判别后端。

准入判断：映射和预算检查无未解释错误；至少能定位基线遗漏与 oracle 可补充的证据差。若同预算候选 oracle 对主基线没有明显空间，停止当前选择器支线，不进入付费六格实验。

### 步骤 B：先固定候选信息，执行六格最小矩阵

| 执行方式 | 通用 LLM 判别 | JEV 判别 |
| --- | --- | --- |
| I：各阶段独立判断 | I-G | I-J |
| C：只缓存相同判断、各阶段决策仍独立 | C-G | C-J |
| S：同一组关系同时参与分块与证据选择 | S-G | S-J |

I 与 C 使用相同任务、同样阶段输入与相同下游策略；仅是否复用完全相同的结果不同。C 是普通缓存强基线。S 才让共享关系影响边界/候选关联和预算内选择；必须记录一个关系如何改变两处决策。若 S 与 C 只有请求次数不同，实验根本没有实现 H1。

**归因模式先于整链路模式**：

- 归因模式：冻结所有可见 atoms、候选关系及候选证据池，复用同一检索得分和后端判别结果，在 I/C/S 下回放策略。S 不可额外获得候选文本或更长上下文。这样优先回答决策机制问题；缓存成本另做冷/热真实执行测量。
- 整链路模式：通过归因门槛后才让 chunk 改变索引与召回；所有方法仍共用原文库、embedding、检索/重排配置和最终预算。此时候选集合自然不同，单列候选召回变化，不能继续声称候选池完全相同。

最小关系执行策略应先限定为可审计的局部边界软势与确定性预算选择；长距离边不强塞为单父树，不声称普通边界 DP 能精确求解任意依赖图。若采用贪心，应标明为启发式，在小实例与枚举上限比较并记录差距。

主比较是 `S-J − C-J` 与 `S-G − C-G`；后端比较是在同一行内 J 与 G 的差。若主张 JEV 特别适合该架构，再报告交互差：`(S-J − C-J) − (S-G − C-G)`。只报告 I-G 与 S-J 的总差不能区分架构、模型及缓存收益。

第一轮不把全部消融展开。必须有修正版规则底座、六格矩阵和候选 oracle；JEV 仅重排、关系打乱、邻居扩展等只在对应机制获得初步支持后针对性加入。公开论文阶段还需具体最近工作复现或严格可比实现，本 pilot 不以六格矩阵替代全部相关工作基线。

## 5. 普通边界分类器与 Refiner 的独立对照

这条训练支线不阻塞步骤 A，也不与六格后端矩阵同时更换数据或模型。

| 项目 | 固定做法 |
| --- | --- |
| 任务输入 | 同一真实固定预算 `b0`，同一 atoms、正文窗口与编码器；合成扰动另列 |
| 编码器 | 同一 BGE-M3 checkpoint、tokenizer、冻结策略与缓存；绑定实际文件 hash |
| 简单模型 | 共用相同文档上下文层和输入信息，单个 gap head 直接预测最终边界；含同样的 `b0` 状态信息 |
| 编辑模型 | 同一 backbone/context，KEEP/DEL/SHIFT(K=6)+INSERT；使用 `slac-boundary-edit-v1` 标签和合法解码 |
| 监督 | 完全相同文档、family、参考版本和 sample weight；仅标签表达不同 |
| 预算 | 同唯一 family 数、可见 token、最大优化步数、早停条件与调参试验数；记录参数量、实际设备时间和峰值显存差 |
| 后处理 | 同一 tokenizer 与 projector；raw、仅 projector、最终 projected 分开评估 |
| 种子 | 正式小对照预定 3 个种子；当前微型训练能运行仅算工程诊断 |

首轮正式学习诊断拟定 16–32 个经过质量验收的训练 family 与 16–32 个不同的诊断 family；单次最多 500 updates、单种子设备时间上限 30 分钟，OOM 不自动扩大显存需求或换大模型。数量和时长是草案上限，吞吐实测后可在任何评价前修订并锁定。不能从旧 repaired legacy 标签直接宣布这些 family 已验收。

只有 H3 出现可解释收益后，再逐项比较弱标签 only、精细标签 only、弱预训练＋精调。共同文档/算力对照与扩量对照分开；预训练和精调共同占总预算，不给混合方案隐含更多更新。参考边界未经独立审核时，分数只能称“弱参考一致性”。普通分类器表现相当即保留较简单模型，不强行保留编辑架构贡献。

## 6. 公平预算与执行账本

草案主设置为 chunk 目标 384 个 **实际编码器** tokens、最终证据上限 2,048 个 **固定生成器** tokens；开发阶段冻结后才运行 pilot，敏感性档暂定 1,024/4,096。二者是不同 tokenizer 的不同预算，不直接与旧 WordPiece 256/512/1024 相等。主预算是否适合真实长文必须先由无模型覆盖诊断确认。

- 编码器 tokens 包含实际 special tokens；记录 atom 输入截断比例。超长不可拆 atom 明确拒绝/隔离或使用共同的可追溯重切规则，不能静默截掉证据。
- 最终提示词包含 evidence、query、指令、引用 ID 的总长也要检查；预留固定回答预算。硬上限下短缺/无法装入记录为失败，不将整题删除。
- 同一 generation model/revision、prompt、sampling policy、max output tokens；Qasper 官方答案不进入提示词。不同方法交错执行，避免系统性时段偏差。
- 同证据预算为首要控制；同时记录实际使用量。等最大预算不代表实际长度相同，因此报告匹配实际 token 档的结果或质量—长度曲线。
- 限定统一可见上下文和候选上限，不能给 S 看全文而让 C 仅看孤立 chunk。证据去重、原文顺序、标题处理、引用展开与无答案策略全部公共化。
- 每次保存 request hash、输入对象 IDs、模型请求/响应版本、prompt/config/data hash、完整返回分布、解析状态、实际输入/输出 tokens、wall time、费用、重试/fallback、cold/warm 标识；不保存认证 header。
- 成本分为离线关系构建、embedding/index、查询判别、最终生成；报告每文档 1/5/10 个 query 的摊销，不能免费忽略离线费用。测 p50/p95 和失败率，不能只拿最低延迟。

拟定 pilot 资源上限：24 个 family、96 个 query；每文档最多 64 个静态关系问题，每题最多 16 个查询相关问题，超限的候选召回损失单列。每后端的真实累计请求/questions/tokens cap 和货币硬上限必须在运行配置中落值后才执行；当前普通 LLM/生成器和实时单价未锁定，**费用待估，不虚构总价**。I/C/S 的重复计算、重试和计时重复全部占上限，不把缓存回放视作零成本实测。

## 7. 评价与分析

| 层次 | 必须保存的指标 | 解释限制 |
| --- | --- | --- |
| 基础合法性 | 原文覆盖/重复、非法 gap、跨序、失败、各 tokenizer 超预算、truncation | 零错误是工程准入，不是语义收益 |
| 边界 | raw boundary F1；projector-only F1；projected F1；编辑/插入率、投影改动率与原因 | 弱参考和人工参考分开；编辑精确匹配只作诊断 |
| 候选 | 同预算 gold 可达上限、标注证据候选覆盖、因候选 cap 丢失的证据 | oracle 非部署，不算模型成绩 |
| 证据主指标 | 已标注证据的原文 token-span 保留率，按原回答证据集合分别计算并保留明细 | 不把集合并集视为唯一必要集合；不等于充分性 |
| 原生 Qasper | 固定版本官方 evaluator 的 answer F1 / evidence 指标；各答案类型分组 | 先验收适配器；不靠自造宽松 paragraph-overlap 冒充原生分数 |
| 独立补充审核 | 隐去系统名后的支持性、遗漏条件/例外、无支持断言、拒答 | 没有实际人员审核则保持缺项，AI互评不冒充人工 |
| 资源 | 实际 evidence tokens、API/离线费用、p50/p95、失败/重试率、索引体积、训练时间/显存 | 质量与成本一起报告，失败计入分母 |

主 evidence proxy 在运行前写清楚数学定义：对每份有效人工回答 `a`，用原文 offset 的 token 集 `E_a` 表示其可定位证据，`P` 表示真正送入生成器的原文 token 集，计算 `|P∩E_a|/|E_a|`；不把一个字符交集算成整段命中。多个回答的汇总规则（建议预先指定 `max_a` 并同时报告各回答分布）在开发集合锁定，不能看过系统输出后选择。图表/无法定位的分母与失败计数单列。此指标独立命名为 proxy，不能覆盖官方评价定义。

paper/family 是配对独立单位。先对每篇题目求平均，再做 family 宏平均；报告每题及每来源/长度组明细。采用固定种子、2,000 次 family bootstrap 估计配对差值的 95% 区间；相关的 query/边界不当独立样本。24-family pilot 的宽区间应称不确定，不包装成正式统计确认。主比较/主预算先锁定，其他探索不择优替代主结果。

## 8. 继续、停止与尚缺条件

以下数值是**拟预注册的实用门槛**，不是已经观察的效果；需在无模型开发诊断后、查看 pilot 系统结果前冻结：

| 判断点 | 暂定门槛与动作 |
| --- | --- |
| 候选上限 | 同候选/预算 oracle 的主 proxy 对合理基线改善不足 5 个百分点时，先诊断候选或任务敏感性，不立即扩大判别调用 |
| 架构继续信号 | S 对 C 的主 proxy 提升至少 3 个百分点、QA 不退化超过 1 个百分点，并有对应遗漏证据被恢复的可追溯实例；区间跨零只算有待扩大验证 |
| 质量相当的效率路径 | QA/证据在上述容忍范围内，完整摊销成本或测得时延下降至少 20%；若仅 C 已实现同样收益，则归于缓存，不主张关系协同 |
| Refiner 退出 | 同预算普通分类器达到相当或更好下游表现；保留简单方案，停止编辑机制扩量 |
| 立即退回修复 | 任意未解释的 span 错位、标签泄漏、版本混入、预算违规、参考无法定位；不把这些样例静默剔除后继续报分 |
| 收缩主张 | 收益只来自更多实际 tokens、旧 bug 修复、同教师评分或更大模型；不宣称新增架构有效 |
| 不确定结果 | 达到预定上限仍不足以判断时，保留负/不确定结论，先做方差/样本量分析；不自动扩数据或反复更换 seed |
