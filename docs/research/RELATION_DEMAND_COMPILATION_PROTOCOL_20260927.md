# Finite relation demand compilation — exploratory protocol

Status: implementation and preparation only. Real influence, decision-depth and compiled results are not computed before this source, tests, protocol and plan are reviewed, sealed and released. This is a new zero-API, zero-gold exploration following the [opportunity protocol](RELATION_OPPORTUNITY_PROTOCOL_20260927.md). It does not amend or admit the original 562-edge paid experiment.

## Fixed input and output identity

Use all 77 exposed development questions in 24 families and all 501 masks from the completed, independently verified opportunity gate. The input has 107 eligible edge–query occurrences; the numbers of questions with 0 through 7 eligible edges are 31, 19, 8, 10, 6, 1, 1, 1. No question or assignment is discarded. The static edge universe originally prepared contains 562 edges, but this stage analyzes only the eligible domains actually represented in these complete cubes.

Each Boolean variable is a source-qualified native boundary `(document, A-unit, B-unit)` with the existing meaning “selected B boosts preceding A.” The same identity in different queries denotes the same hypothetical global Boolean. No real relation label is obtained or selected.

For each query, define `F(mask)` as the entire tuple of ordered source-qualified selected identities, exact UTF-8 rendered evidence string, its SHA-256 and actual saved BGE evidence-token count. Rendered headers and source order remain unchanged. Tokens are inherited from the independent whole-pack tokenizer reconstruction; this stage loads no tokenizer. It validates selected-unit provenance and exact rendered bytes against the saved gate output. Equal text/hash with different selected identities or token counts is a different terminal. This is an exact output/pack preservation contract, not trace equivalence or a claim to the smallest possible text-only decision diagram.

## Fixed compiler and exhaustive verification

An edge is globally essential **for one query** if there exists a pair of assignments in its complete cube differing only in this edge whose full outputs differ. Single zero/full-mask comparisons do not suffice. Local irrelevance is the complement of that full-cube essential set. A static edge can be called irrelevant across this batch's eligible domains only when it is nonessential for every query in which it occurs.

At each decision state, consider the remaining subcube after all prior answers. If all complete output signatures are equal, emit that terminal immediately. Otherwise ask the first conditional-essential variable in the original native boundary order. Conditional essentiality uses a one-bit-flip witness entirely within the current subcube. Recurse on false/true, intern identical full terminals and identical ordered decision triples, and collapse equal branches. Do not search for a better variable ordering or use quality, answers, favorable masks, observed labels or fees to choose one.

An independent pointer traversal, which does not invoke influence testing or compilation, evaluates the resulting DAG for every original assignment. Every output must equal its frozen `F(mask)`, including selected identities, exact pack, hash and actual tokens. Validate graph references, acyclicity, increasing variable order and reachable nodes. A malformed or incomplete cube, unknown source identity, duplicate assignment, bad terminal, any mismatch or deadline failure prevents a complete result.

No actual cross-query cache schedule is run. In addition to empty-cache DAG traversal, verify the intended cache runtime exhaustively: condition on **all** already cached source-qualified Boolean variables before choosing the next conditional-essential variable, and cache each newly asked edge exactly once. For every query, enumerate every full assignment and every subset of initially known variables, initializing cached values from that same hypothetical assignment. The fixed edge-count histogram gives **4,075 distinct ternary partial-cache subcubes** (`Σ3^m`) and **23,915 assignment/known-subset paths** (`Σ4^m`), which can be calculated during preparation without influence or depth analysis.

An independent oracle callback reconstructs the compatible subcube and checks that every request is the canonical first variable whose complete cofactors differ, never rereads a known variable, and returns its consistent hypothetical bit. Verify constant-subcube early stopping, cache consistency and full `F` equality for every path. These partial states cover any globally consistent cache restriction at entry to a query; they do not select one real global labeling or simulate the 77-query global schedule. Distinct global queries sharing an edge also have a synthetic consistency test. The complete per-query proof covers all consistent global assignments as a subset; it does not imply that separately listed per-query masks form one realized global labeling.

The two runtime checks have distinct implementations: empty-cache execution traverses the compiled DAG by pointers; the cache-aware reference scheduler restricts the truth table and recomputes cofactors/influence at each step. Efficient restriction of a compiled DAG and deployment inference are **not** implemented. The 23,915-path check must not be described as measured warm-cache DAG execution or as a production performance result.

This is an application of established ordered, finite-terminal decision diagram ideas, not a new BDD algorithm. Fixed ordering need not minimize node count or requests. The separate [design review](RELATION_DEMAND_DESIGN_REVIEW_20260927.md) documents the primary sources and formal control boundaries, including [Bryant's ordered decision diagrams](https://www.cs.cmu.edu/~bryant/pubdir/ieeetc86.pdf) and [Bahar et al.'s finite-valued terminals](https://link.springer.com/article/10.1023/A:1008699807402).

Content-essential information does **not** complete the original placebo experiment or its full-domain label-count contract. For example, `F(a,b)=a` makes `b` irrelevant to content, but swapping the two source labels gives `F(P(a,b))=b`, so placebo still needs `b`. Unqueried edges are unobserved, never automatically independent/unknown/no. This stage neither preserves the original 562-label inventory nor changes the original placebo domain; a future experiment must separately derive `F ∘ P` and any required stratum counts, or explicitly freeze a new control protocol.

## Prespecified aggregate outputs

Report eligible and essential unique static-edge union counts, globally irrelevant edges within that eligible union, essential and locally irrelevant edge–query occurrence counts, per-question essential-count/minimum-depth/maximum-depth histograms, all-501-assignment depth histogram, total decision and terminal node counts, and exact output equality counts for all 77 queries and 501 assignments. Keep all histograms, including zeros. Do not select or deploy a particular mask.

Also report verified partial-cache subcube/path counts and the complete 23,915-path additional-request histogram. This is another combinatorial histogram, not an observed cache hit distribution or expected online cost.

The essential static-edge union is a safe upper bound on distinct relation requests with a shared cache. The sum of each query's separate maximum depth is also a safe upper bound; their minimum may be reported as a combined safe bound. Neither is claimed to be the exact worst case of a shared-cache global labeling/schedule. The 501-mask histogram weights queries by cube size and is a combinatorial inventory, not a uniform-question mean, a relation-label probability model, or expected API cost. There is no fee estimate, proportional conversion from removed edges to dollars, new API payload or spending admission in this stage.

Here and in output field names, a “request” counts a logical binary-label access. It does not count an HTTP request, model invocation, input/output tokens or provider charge; batching may change all of those quantities.

## Provenance, execution and interpretation

The fixed independent gate receipt SHA is `ebf959058e67a2ea3285f70c985f0a94bda2d6912cd6eab24d4de1a33037e32c`. Directly consumed inputs are that receipt, gate plan/cases/seal, four complete gate output files, and its public protocol. Every direct file must match the external receipt's commitments, and direct source inventories and bytes are checked before and after use. Bind the new source, tests and this protocol as well. The receipt's unused 33-file commitment map and the original upstream 2,564 commitments are inherited provenance; this stage does not reread their unused QA, request, tokenizer or weight files.

Preparation projects the already verified records into complete cubes and checks source identity, render bytes and inventory only. It may not call influence testing, compilation, traversal/depth analysis or aggregate evaluation. The resulting new plan, cube file and seal bind a single new run directory. Run and audit use only these frozen inputs; they are serial stdlib CPU work with a 300-second cooperative deadline, including source validation and final publication checks. A failed or interrupted run is not resumed and has no completed summary. The complete audit recompiles and replays every result and validates all public and summary metadata. Measured timing is a saved measurement, not independent latency proof; an external watchdog is separate.

Private identities, evidence text, cubes, diagrams and per-mask/per-question records remain ignored artifacts. Public aggregates contain no such fields, query strings, answers, gold references or quality scores. No API, training, model inference or QA-sidecar access occurs.

This study is conditioned on a fixed binary oracle and already exposed support/candidate/packing decisions. Online model stochasticity, different batch context and routing can produce different relation labels. The formal equality does not prove that two different API execution plans will observe equal predictions. Finite cube construction is exponential in variable count (at most seven here); it is not evidence of scalable deployment. Output equivalence and a request upper bound establish neither relation accuracy, better answers, latency savings, exact costs nor cross-stage relation-sharing benefit. Any such claim requires a later frozen experiment and independent evaluation.
