# 查询范围保留：六题审查与相关工作

2026-10-04。**上一轮 JEV 能区分两个明确问题对，不意味着这些改写可以替代原自然问题。** 本轮尚未建立四个改写目标对原要求的完整覆盖，并识别了主体、用途或提问目标的转换；即使其判断完全正确，拼接不同问题下的 gain/loss 仍可能批准有损交换。同时，“问题分解＋覆盖判断＋证据选择”已有直接先例，不能作为当前新增方法的创新主张。

本轮新增模型 API 调用、训练和本地模型推理均为 0。只对已有六题的问题文本、四个已执行的改写问题做审查，另查三篇公开原始论文，没有全量检查数据集、读取新问答或改动旧标注。[聚合记录](results/query_obligation_audit_20261004.json)区分人工审查、精确集合反例和文献判断。

## 原问题要求什么

两份分别保存的 AI 审查从问题文字提取主体、任务、限定与复合需求。双方已有先前上下文，因此不是盲审；下表是非穷尽的需求解释，不能充当所有相关事实的金标准。A 的 19 处锚点可在原问题中精确定位，但“提取项有来源”不等于“提取完整”。

| 原题 | 至少要保留的需求或解释分支 | 不能替代它的局部信息 |
|---|---|---|
| 1 | 在指代的模型和参照数据集范围下，是否**还**尝试了**其他**数据集；try 的含义须由上下文支持 | 仅知道一个评测数据集名称；未经指代确认就换成某基线的训练来源 |
| 2 | 实际使用的词级**和**字符级基线，并保留各模型与类别的对应 | 嵌入了哪些对象；某个被引工作曾取得什么结果 |
| 3 | 判断所指垃圾检测方案是否无监督，并区分整套方法与其中的 LDA 组件 | LDA 本身无监督，或某个特征构造细节 |
| 4 | 基准数据集身份**以及同一数据集的质量判断**；质量含义不明确时保留不确定性 | 只给名称；用模型表现代替数据质量；把一项限制扩大为整体质量结论 |
| 5 | 在所指采集或提取范围内识别主题，区分采样来源与语义主题的可能解释 | 平台可能包含的示例主题，或仅说主题多样 |
| 6 | 识别作者构建的所指预测模型，需要时用预测任务消除多个模型之间的歧义 | 不同任务的另一个模型；默认所有训练细节都是必答要求 |

这些问题有些需要文档或对话上下文解析指代。当前问题文字本身不能保证唯一解释；不能为了生成一个易判断的标签就悄悄固定主体、质量标准或任务范围。

## 四个改写都没有建立替代资格

| 上轮改写 | 相对原题的覆盖缺口 |
|---|---|
| Q1 | 将未解析的模型与 try 限定成具名基线和补充训练来源；没有证明这种主体与用途选择就是原题所指 |
| Q2 | 从“是否还有其他数据集”转为某个评估数据集的名称，尚未证明完整保留参照范围与额外数据集判断 |
| Q3 | 从实际使用的两类基线转为被引用的字符模型结果 |
| Q4 | 从两类基线身份转为词级替代模型的嵌入对象，字符级基线分支也未覆盖 |

Q1/Q2 合在一起、Q3/Q4 合在一起，也没有自动建立原需求的完整覆盖。这不否认这些问题作为[局部敏感性诊断](LOSS_SCOPE_JEV_RESULTS_20261004.md)的有效用途；它否决的是把那次 2/2 成功区分解释为原题已经修复。原问题、原模型输出、先前 A/B 标签及暂缓的 Q5/Q6 均保持不变。

## 两个不依赖模型错误的反例

第一例设原问题需要 a、b、c，S 支持 {a,b}，T 支持 {a,c}，改写只问 a。原问题下 gain=yes，改写下 loss=no，两包内部均可无冲突；但原问题需要的 b 确实丢失。错误来自混用不同问题的判断，不需要任何一个判断器出错。

对应到一个人工基线问题：保留词级模型的嵌入对象，删除“采用字符级基线 C”，加入“词级基线名为 W”。原题获得 W，改写 Q4 的对象列表不受损，但字符级基线身份消失。该例为人工逻辑反例，不是又一次自然模型错误。

第二例设 S 的关系为 {(词级,A),(字符级,B)}，T 为 {(词级,B),(字符级,A)}。若只分别检查“有哪些类别”和“有哪些模型名称”，两个投影都不变，但类别与模型的对应关系已经改变。足够丰富的联合关系需求可以发现它；这不是说所有分解都失败，而是平面清单逐项保留不能替代关系保留。

这两个有限集合运算可精确复算，不涉及数据集枚举或新的模型结果，也不是新数学定理。如果要用若干子问题的无损结论推出原问题无损，必须另外证明：每一个与原问题相关的丢失信息，都在至少一个被检查子问题的语义范围内，而且采用一致的整包支持定义。只保存几个正确的子判断、原文锚点或最短答案，均不提供这个覆盖保证。

## 直接相关的已有方法

| 原始论文与查阅范围 | 与当前设想的重叠 |
|---|---|
| [SEAL-RAG：Replace, Don't Expand](https://arxiv.org/html/2512.10787v1)，§3.2–3.5 | 记录实体、关系、限定条件与来源；从查询形成需求和缺口，判断覆盖，再在固定容量内交换证据。显式需求、来源锚定或固定容量替换本身都不是新的区别。 |
| [Do RAG Systems Cover What Matters?](https://aclanthology.org/2025.naacl-long.301/)，NAACL 2025，§3、§5、§7及附录 A | 用子问题分解和覆盖判断评价内容，并以核心子问题的覆盖组织检索与重排；论文也承认复杂或含糊问题可能分解不完整。 |
| [QUBO-Optimized Evidence Selection](https://arxiv.org/html/2607.12334v1)，§3.1–3.3、§4 | 根据模型生成的需求及支持标签做集合选择，目标包括部分/直接支持、覆盖、冗余和互补性。把需求覆盖纳入优化已有近似方案。其语义预处理仍需模型，不能把优化器本身当成零模型成本。 |

这是三篇论文相关方法与局限章节的定向查阅，没有复现它们的结果，也不是完整综述。当前只把明确描述的方法作为概念对照，不以论文中的性能数值或未复现的成本主张替代我们的实测。在所查方法中没有看到与本项目相同的整包无损约束，也不等于这个更窄的约束具有新颖性。

## 本轮决定

不新增“先缩窄问题再放行交换”的选择器，也不以普通需求分解包装新的框架。原始 query 必须继续绑定 gain、loss 和证据包；辅助表示若遗漏范围，不得借其 no 覆盖原问题的 yes 或 unknown。保持原问题是一项必要约束，不是已经有效的新算法。

进一步机制探索至少要同时面对三个问题：能否发现分解遗漏或关系归属改变；能否在阻止有损交换时仍保留有益交换；相对未分解判断、普通分解覆盖和同成本控制是否有增量。若只是多一次检查后全部拒绝，或把语义变窄后更容易得到 no，都不构成所需改进。

因此，本轮收回直接改写的修补路径，保留上一轮测得的局部 JEV 能力；后续回到保持原问题不变的机制与来源信息增量审查。当前还没有通过新颖性与效果验证的新算法，不开启新的 API 计划或恢复旧大规模实验。
