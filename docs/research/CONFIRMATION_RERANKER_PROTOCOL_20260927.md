# Confirmation reranker evidence stage, 27 September 2026

This local stage implements only the already fixed `reranker_k3` arm. It consumes a completed confirmation candidate run's `prepared.json`, `summary.json`, `sample_check.json` and its successful audit receipt. Those four consumed files are freshly bound. Other parent commitments are retained as inherited commitments, without reopening the original export, references, QA sidecars, archive, or prior quality results. It retains every question and every support pair from the same given-document top-eight plus native-neighbour candidate pool, capped at sixteen units per question. Counts are derived from the complete parent inventory; there is no old 77-question quota.

The model is BAAI/bge-reranker-v2-m3, revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`, from the existing local snapshot. The expected `model.safetensors` size is 2,271,071,852 bytes and SHA-256 is `d9e3e081faff1eefb84019509b2f5558fd74c1a05a2c7db22f74174fcedb5286`. Preparation checks weight existence/size and hashes only the small tokenizer/config files. A run streams the complete weight file exactly once for verification immediately before model loading. The BGE evidence tokenizer remains pinned separately.

Prepare tokenizes every raw question/canonical-unit pair with special tokens, without instructions, padding or truncation. It records the full pair inventory, token IDs, token hashes and length summary before testing readiness. Before this stage's first real preparation or inference, its model-input guard is set to the native 8,192-token context, extending the old development stage's 1,024-token input guard. This preserves complete pairs; it does not increase the separate 1,024 BGE evidence-pack budget, change scoring or alter the frozen development source. No new reranker logits or quality outcomes informed this decision, and no failed preparation is implied. The summary still reports the number of pairs above 1,024 tokens. A pair above 8,192 tokens leaves an immutable `not_ready` preparation with a complete length summary; it cannot be dropped, silently truncated or inferred. All structural failures also leave `not_ready` and do not admit GPU inference.

An explicitly idle GPU is required, using the existing conservative read-only process/utilization gate. Inference is a single run with a new relative 1,800-second watchdog covering weight validation, model load, all pair inference, packing and output. It does not revive an old absolute deadline. The watchdog stops only its own process. FP16, SDPA, microbatch four, raw single classification logits converted to FP32, no sigmoid/normalization, and the original complete-pair padding checks are retained. The process reserves at most 7 GiB and stops if observed allocation exceeds 6 GiB. No API, training, automatic retry, model fallback or CPU inference fallback occurs.

For each question, sort all candidate units by descending raw score, then original dense rank, then native source order. Scan that order, skip exact native-text duplicates, and skip a unit when the complete rendered prospective pack exceeds 1,024 BGE tokens. Select at most three units and render in native source order using the unchanged `[unit_id]` format. Save every pair score with its frozen identity and every question's ranking and `reranker_k3` pack. No reference answer, support label or metric is read or calculated. A complete selected pack is for later uniform answer generation, not a quality result.

Auditing checks complete coverage, identity, finite scores, source/output hashes and pack structure. Saved-score ranking and actual token packing are replayed with the same functions only on the fixed salted sample inherited from the candidate stage: at most eight documents and two questions per document. Sampled pair token IDs are checked against text, while complete length and padding summaries are mechanically reconstructed from saved IDs; finite elapsed time, saved dtypes and GPU memory limits are checked. There is no model rerun, full numerical replay or independent-algorithm claim. The full candidate computation is the work, and the sample is a numerical and structural spot check. Timing is local execution time, not production serving or end-to-end RAG latency.

All raw identities, text, scores and packs stay under the ignored research artifact root. Public outputs contain aggregate counts, lengths, resource use and hashes only. OOM, timeout, malformed scores or source drift stops the whole run and prevents a successful summary or partial main result. This stage adds no method, selects no cohort and grants no paid-execution or statistical-independence admission.
