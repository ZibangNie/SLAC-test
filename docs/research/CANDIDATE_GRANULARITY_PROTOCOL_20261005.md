# 固定候选范围内的本地评分粒度干预

2026-10-05。复用此前两题及其原始 16/14 个候选来源单元，不换题、不扩候选域，不训练、不调用 API。先前参考和结果已经曝光，因此这是一项开发性机制诊断；以下规则在本轮新模型输出之前固定，不能称未曝光确认。

此前完整文档的参考辅助检查显示，相邻来源区间合并能消除部分块数差异。这次改用不读取参考的实际评分与选择，检验完整单元与细分 atom 的评分输入是否改变来源内容选择。已知第二题两份 annotation 范围不同，其中一份还有候选缺失，因此保留全部 annotation，分别报告候选覆盖上限，不混合或挑选有利标注。

## 输入与评分

两臂仅采用保存的 raw-b0 来源块和其中全部 source atom，均直接使用各自完整原文切片。只取原候选 native Unit 对应的 raw-b0 块，不读取全语料或重跑 atomizer。单位臂与 atom 臂的允许字符集合必须完全相同；raw-b0 块包含原来源映射里的分隔空白。它们不等同于旧规范化检索文本，故不能继承旧 BGE/JEV 分数。

用现有本地 `BAAI/bge-reranker-v2-m3` 的固定 snapshot `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e` 为两个粒度的新文本直接评分。相同 query/passage 字符串只推理一次并共享该次分数，避免把同文本的数值波动当作粒度差异；不同文本不得搬运、求和或最大化旧段落分数。最多 281 个唯一配对；准备完成后固定实际配对数，不补样本。完整输入对最多 1,024 模型 tokens，禁用截断；超限则保留失败，不改内容。

采用既有本地运行器的 CUDA FP16、SDPA、microbatch=4、模型哈希及 GPU 准入检查。子运行上限 180 秒，父进程上限 300 秒；无自动重试、CPU 回退、下载或训练。模型运行与预算 tokenizer 分别计数，不将本地推理描述为零模型调用。

## 同一输出预算下选包

每臂独立按新 raw logit 降序排列，同分依次按原 Dense 的 parent Unit 排名、原文起止位置排序。logit 不是校准概率；不设语义阈值，不使用参考来选择停止位置。

按排序单次扫描所有候选。每次尝试加入一项，将已选且接触的原文区间合并；只有输出区间最多三段、生产 source renderer 整块 BGE proxy tokens 不超过 1,024 才接受。超限跳过并继续，不提前因已有三段而结束，也不回头重试已跳过项。不跨空隙、不裁剪候选，不按文本去重不同来源位置。两臂共用这一规则，但候选数量、前缀可行性和最终实际长度仍可能不同，因此结果不能独立归因于模型理解能力。

使用和上一阶段相同的最小 metadata、来源顺序、区间 chunk ID 和完整 `render_evidence_block(..., preserve_source_text=True)`。代理预算不含系统指令、独立 query message、供应商 framing 或输出。它不是供应商收费 token 或完整上下文预算。

## 冻结后评价及判断边界

先保存四个完整选包及 hash，再读取已保存的四份参考区间。分别记录全部八条 annotation×方法的字符交集、字符 precision/recall、完整覆盖、实际来源字符数和整块 tokens；不把部分段落命中当作整段，不套用原生段落 Evidence F1，也不生成答案或 Answer F1。

同时对同一四份参考报告原候选域及旧 JEV 三单元选集的完整参考单元数与字符覆盖。候选域外缺失不能归因于本轮排序，更不能用全篇 oracle 扩展候选后声称评分粒度有效。

若统一输出后来源集合完全相同，或 atom 臂只增加成本／降低完整参考覆盖，停止把这次结果作为扩展 JEV 调用的理由。若有改善，也仅保留为后续小型跨模型机制探测的动机；必须结合全部 annotation、成本和上下文差异解释，不宣称泛化、语义收益或论文创新。
