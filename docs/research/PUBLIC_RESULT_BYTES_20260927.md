# 公开聚合的字节一致性修正

2026-09-27。核查28个已有公开JSON/SVG后发现，23个工作区文件与当时Git blob的差异仅为CRLF被转换成LF。JSON值和图形内容没有变化，但若报告引用本地原始产物的SHA-256，转换后的Git文件不能通过该原始字节校验。

本次将公开JSON/SVG设为Git `-text`，重新保存这些文件现有的封印字节。没有重写科学source、plan、run、请求响应、账本或旧审计；没有重跑实验、调整数值或重算置信区间。SVG中既有的生成式路径空白作为原始字节保留，Git仅对这些生成产物允许相应行尾空白。源代码和普通研究文档仍使用正常文本检查。

[字节清单](results/public_result_bytes_20260927.json)记录这28个公开文件的当前SHA-256、此前Git SHA及是否曾受换行转换影响。清单不包含自身，不含数据身份或原始文本。发布前逐个检查暂存Git blob与工作区文件字节完全相等。今后新增公开产物应优先直接导出LF；已有封印产物必须保持其原始字节，不通过格式化“修复”旧来源。

本轮candidate oracle另有一份明确的导出格式记录：公开JSON/报告在首次发布时按LF规范化，JSON对象与原始发布器输出完全相等；图的格式修正前后PNG像素完全相同。原始发布器输出保留于本地忽略目录，不覆盖；该阶段公开文件的hash以本清单为准，其科学run和独立审计hash不受影响。

这修正的是公开副本的字节可复查性，不等于公开仓库包含所有私有数据、响应或模型权重，也不消除旧artifact迁移中的绝对路径依赖。
