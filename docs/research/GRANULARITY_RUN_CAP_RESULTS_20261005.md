## 干预改变了选择路径

无段数上限时仍会受到 token 上限约束。C 在第一题为 16 次接纳／36 次 `skip_tokens`，第二题为 18／27；原 `cap3` 中则分别为 15／37 次 `skip_runs`、12／33 次 `skip_runs`，没有 token 拒绝。原来未计算的拟选包预算，在本轮放宽段数约束后按完整文本逐项测量。

新 C 包不是旧包加上一些候选：第一题删除旧包 749 个来源字符并加入 776 个，第二题删除 365 个并加入 1,368 个。改变早期可行性会改变后续拟选包及拒绝原因；因此不能把净增 279 个参考字符简单解释为独立救回若干旧拒绝项。A/B 在第二题完全不变，第一题两者均发生来源集合变化，但仍没有标注覆盖增益。

这一对照解释当前固定流程的行为。`no_cap` 的部分结果超过三个输出区间，并非满足原约束的新算法；它也未证明这类上下文更利于生成答案。

## 原末态的独立几何检查

另一个只读检查针对原 C 的全部 70 个 `skip_runs`，每次将一个候选独立加到原最终包，只合并相邻区间、不累计加入。第一题 37 项中有 1 项最终只需三段，第二题 33 项中有 5 项；其余 64 项仍需四段。

这证明少数候选的段数拒绝条件在后续选择后已经消失，但该检查没有测量这些末态新增包的 tokens，没有生成新的预测包，也没有证明回访能够改善指标。当前自然例子仍需要把“曾被拒绝”“末态几何可行”“完整预算可行”和“回答相关”分开。
