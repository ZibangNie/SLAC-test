# Gold-free confirmation candidates, 27 September 2026

This new local stage consumes only the completed restricted export's `documents.jsonl`, `questions.jsonl`, and `summary.json`. It never opens references, question-answer sidecars, the original archive, or old quality outputs. The export's other hashes are inherited commitments, not fresh validation claims. The operational component is `family_id`; `original_family_id` remains separate. All exported documents and all questions are retained, without answer-based filtering or a fixed question quota.

Preparation validates identities, exact unit fields and complete coverage, loads only the pinned local BGE tokenizer, and saves complete untruncated token IDs for every unit and question. The encoder input is canonical unit text alone or question text alone, without instructions. Invalid structure or any input above 8,192 tokens leaves a new `not_ready` preparation artifact and prevents inference. It does not silently truncate, split or discard records. Plan loading checks every saved token length and reconstructs the length summary mechanically; text-to-token replay is bounded to at most sixteen sampled questions and two sampled units per sampled document. All output directories must be below the ignored research artifact root.

The model is BAAI/bge-m3 revision `5617a9f61b028005a4858fdac845db406aefb181`. Its expected weight SHA is inherited from the completed dense baseline; preparation only checks the weight file's existence and size. A single streaming hash of the weight file is required immediately before loading it for a run. Small tokenizer and directly used source files are bound separately. This is not a repeated audit of the old experiment's complete ancestry.

Run is single-use, uses one explicitly admitted idle GPU, and has a relative hard runtime of at most 1,800 seconds covering weight verification, model loading, encoding, candidate construction and output writing. The old night's absolute deadline is not reused. The existing conservative idle process checks are reused, including the user-game check and the fixed verified host UI exception. A watchdog terminates only its own run process on timeout. OOM, malformed output, source drift or timeout fails the whole run; there is no automatic retry, CPU fallback or partial successful candidate result. No API is called and no training occurs.

Inference uses FP16, microbatch four, no truncation, CLS pooling followed by FP32 L2 normalization. Vectors are saved as FP32. The local process uses at most 7 GiB reserved GPU memory and stops if observed allocation exceeds 6 GiB. Each question ranks every native unit of its given document by FP32 dot product, breaking ties in native source order. All eight dense seeds are retained; immediate previous then next units are added in seed rank order up to a total of sixteen. Candidate storage remains native source order; candidate ranking preserves the full dense ranking. The support-task manifest contains exactly one query-unit pair per candidate. It contains no static relation tasks.

The `dense_k3` baseline greedily follows candidate dense order, skips exact native-text duplicates and whole packs exceeding 1,024 BGE tokens, and stops at three units. Evidence renders `[unit_id]` and full canonical text in native source order. Token counts include headers, separators and special tokens; empty evidence is zero. No labels, answers, references or metrics participate.

Every query receives a full ranking, candidate mapping, support tasks and a dense pack record. Audit checks complete identities, counts, output hashes and embedding shapes, then uses saved-vector same-function replay for rankings, candidate expansion and packing only on a deterministic sample: up to eight documents and up to two questions per sampled document, at most sixteen questions. Sampling uses a fixed salted identity hash, not text, labels or performance. This bounded sample is neither an independent algorithm nor a full numerical audit. Full candidate computation is the stage's work, not duplicated quality inspection.

The resulting private artifacts support subsequent reranking, exact support-request planning and whole-cohort budget calculation. This stage does not admit a paid run, establish dataset independence, choose a new cohort or produce confirmation scores. A complete generation payload inventory remains dependent on the later complete support decisions. Public output contains only aggregate counts, token/resource summaries and hashes.
