# SLAC 来源信息与机制筛查

2026-10-04。本轮使用已有源码和固定的三文档、六案例副本，新增 API、模型推理、训练及原始语料扫描均为 0。三个方向均未达到新方法实现或模型实验的准入条件。具体进展是厘清了真正可用的来源信息，并排除了当前样本中的重叠压缩机会；没有新增质量结果。

## 实际可用的信息

[原文桥接](../../SLAC/retrieval/decision/native_bridge.py)只复制文档身份、单元身份、原始顺序和文本，明确排除 path、score、role 等字段。[交换判断](../../SLAC/retrieval/decision/exchange.py)当前使用 plain contract，不能把本地存在关系记录理解为已向 JEV 提供这些关系。

[Qasper 导出器](build_qasper_native_chunks.py)保留字段 kind、section_group、JSON pointer、原文与检索文本坐标、hash 及 leaf→owner 映射。它的真实章节路径只有一层；owner 是同章节内的规则分组。不同 leaf 与不同 owner 各自形成分区，混合 owner 与其 leaf 才可能重复覆盖。一般 SLAC schema 中出现 parent/path 字段，不保证每个数据实例都有真实层级。

[打包器](../../SLAC/retrieval/pack/evidence_packer.py)中的 `sibling_support`、`neighbor_support` 等 role 来自检索命中类型，表示检索路径。它们不能证明语义支持、作者归属、训练/评测用途或某项信息对原问题的必要性。章节归属也不能直接给出这些语义结论。

## 固定样本检查

只读取已保存的三篇文档副本（193 个来源字段）及原六例的证据包，没有打开完整语料、答案或新增结果。每例旧包 S 与新包 T 都有三个单元，四单元并集 U 仅用于比较；U 不是实际生成包。原问题、候选和文本全部未改。

| 检查项 | 结果 | 正确解释 |
|---|---:|---|
| U 中的案例—单元出现次数 / 独立来源单元 | 24 / 23 | 一个来源单元出现在两个案例中 |
| 每例 U 内具有正长度原文区间重叠的单元对 | 0 / 36 | 此样本没有同源重叠可压缩；不涉及语义重复 |
| 同时存在同章节与跨章节单元对的案例 | 4 / 6 | 分组信息存在，不证明它与问题相关 |
| U 中可关联来源标题的出现次数 | 23 / 24 | 其中一项是 abstract，不属于章节正文 |
| U 中关联标题也在 U 内的出现次数 | 3 / 23 | 两项是标题自身；另一项正文与标题分别属于换出和换入单元 |
| 实际 S 的正文—标题同时在包内 | 0 / 17 | 17 为六个 S 内正文出现次数 |
| 实际 T 的正文—标题同时在包内 | 0 / 15 | T 另有两个标题单元，但不与其正文同时出现 |

U 中有 20 次关联标题缺失，对应 13 个不同的缺失标题来源单元。不能把 20 写成不同标题数量，也不能把 U 中的 3 次标题可见写成三个正文已具备标题上下文。标题缺席本身并不证明信息不足：正文仍可能独立说明主体和用途。

独立实现核对了三个文档 hash、193 个字段的来源边界、36 次 S/T 单元出现、六例换入换出身份、36 个 U 内区间比较以及所有聚合计数。原计数正确；上表按独立复核要求区分并集、实际证据包、正文和标题自身。公开[聚合记录](results/slac_source_mechanism_screen_20261004.json)只保留计数、结论与审计 hash。

## 三个方向的决定

| 方向 | 现有 X → 拟增加 Y → 待解决 Z | 本轮决定 |
|---|---|---|
| 来源范围绑定 | 逐段及整包判断 → 来源范围与主体/用途的明确对应 → 保留词项却错配主体或任务 | 暂不实现。结构来源可验证，但尚无超出普通标题上下文的语义绑定机制；补入大多数标题属于新增文本，必须计费、计入预算并提供给文本对照。 |
| 同源重叠压缩 | 多粒度完整块打包 → 合并同一文档版本、同一来源位置的重复覆盖 → 腾出容量加入新信息 | 当前样本无机会，且普通区间并集是必要基线。不能把相似文本或不同位置的相同文字视作同一来源出现。 |
| 显式定义依赖 | 现有原文缩写链接 → 按原问题需求补足必要定义 → 避免丢失回答所需的解释 | 不重新启动。[既有六题检查](NATURAL_DEFINITION_OPPORTUNITY_20261004.md)尚未找到超出邻接和额外候选内容的必要机会；本轮没有新见证。 |

这不是“所有结构方法无效”的结论。它限定当前实现、固定样本与三个具体主张，也不撤销旧 JEV 排序的开发性信号。

## 与已有方法的边界

有限核对四项一手来源，未做穷尽性新颖性检索：

- [SEAL-RAG，§3.2–3.5](https://arxiv.org/html/2512.10787v1)已经包含有原文支持的实体、关系、角色等限定信息及固定容量替换。增加一个角色字段或证据账本不足以构成区别。
- [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)通过文档上下文前缀补足块内缺少的实体、时期等信息。使用真实标题可改变来源可靠性和成本，但普通上下文补全本身已有先例。
- [LlamaIndex AutoMergingRetriever](https://developers.llamaindex.ai/python/framework/integrations/retrievers/auto_merging_retriever/)已实现根据父子关系合并检索节点。若新方案的全部作用由来源区间并集解释，应归为工程基线。
- [Late Chunking，§3–3.1](https://arxiv.org/html/2409.04701v3)在上下文编码后形成块向量，并处理长文编码窗口的重叠。编码含有上下文，不代表该上下文已作为原文证据展示给生成器。

仍值得离线检查的狭窄问题是：保持原问题和全部可见来源文本不变时，能否找到普通标题上下文仍无法解决、但有真实来源见证的主体或任务错配。必须同时给出有益新增与有损错配的区分，且明确语义关系从何而来；只有全部拒绝的门控不满足要求。若没有这样的具体见证，就结束这一分支，不以加字段、改名字或扩大 API 样本维持主张。本轮没有批准新模型实验，旧 900 题付费计划继续暂停；持续探索的低 API 范围保持有效。
